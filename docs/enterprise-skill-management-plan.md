# 企业 Skills 接入设计

当前已实现：上游 MCP Skills 扩展透传；企业本地 `.zip`、`.tar.gz` 与公开 GitHub 仓库导入、固定提交号、文件摘要与不可变版本、管理员预览、发布／停用、部门与员工授权、员工目录和企业专用 Streamable HTTP MCP 入口。Go 回环测试覆盖协议、导入格式和撤权；真实 Web／桌面 Host 加载与批准验收仍待完成。

## 先区分两件事

1. **MCP Skills 扩展兼容**：某个已登记的上游 MCP 服务本身发布 Skill。Admin 网关读取该服务声明的扩展能力，透传 `skills/list`、`skills/get` 和技能文件的 `resources/read`。Skill 的来源、内容与版本仍由上游维护；员工是否能看到它，沿用该 MCP 连接的入口授权。此路径已有代码与回环协议测试，不形成企业 Skill 资产。
2. **企业 Skill 资产管理**：管理员把企业自己的 Skill 包纳入 Admin，审核固定内容版本、分配使用范围，再让 Web／桌面 Harness 或其他客户端发现和加载。它需要独立于 MCP 服务的资产、版本、授权与审计模型。Skill 可以引用 MCP 工具，但不应自动继承该工具权限。

两条路径可以并存：同名 Skill 以“来源连接或企业资产 ID + URI”区分。客户端不能只用 Skill 名称作为身份。旧版 MCP 客户端若不支持 Skills 扩展，仍可使用工具和普通 resources；企业客户端是否支持自动发现、完整性校验与用户批准，需要单独联调。

## 企业资产首版边界

- 当前输入支持本地 `.zip`、`.tar.gz` 和公开 GitHub 仓库。GitHub 分支或标签先解析为固定提交号，可选择仓库中的 Skill 子目录；仅访问受限的 GitHub 官方端点。只接受一个 Skill 根目录中的 `SKILL.md`、`references/`、`assets/` 和 `scripts/` 等普通文件。拒绝绝对路径、`..`、符号链接、设备文件、重名路径、超过资源数量或总字节上限的包。
- `SKILL.md` 必须含合法 YAML frontmatter 的 `name` 与 `description`；名称与目录名一致。保留完整 frontmatter，不自行把 `allowed-tools` 当作 Admin 授权。
- 导入生成不可变版本、逐文件 SHA-256 摘要与完整清单。管理员可在发布前预览文本、文件树、脚本以及各版本清单摘要；可视化版本差异尚未实现；审批所绑定的是摘要，不是可变名称。脚本不在 Admin 服务端自动运行。
- 初版状态为草稿、已发布、已停用。更新产生新版本，旧版本保留审计；发布或回退显式指定版本。撤销发布后，新的目录与文件读取立即拒绝；已被客户端复制到本地的文件须由客户端按自己的缓存与撤销规则处理，Admin 不能声称远程删除。
- 授权按企业、明确选中的部门和员工保存，与 MCP 连接授权分开。若 Skill 使用 MCP 工具，实际工具调用仍以 MCP 连接的当前权限为准。页面须同时显示“可读取 Skill”和“可调用其依赖工具”是两个判断。
- 管理界面在“AI 资源管理”下增加 Skill 资产入口：列表、版本、文件预览、授权范围和使用说明。员工目录只返回其获准版本的元数据与资源 URI，不返回未授权文件。

## 接口与协议路径

管理 API 需要按现有 Session、CSRF、权限与审计约定新增：导入、版本列表、版本详情、文件预览、发布／停用、授权替换；每个新增接口同步测试与 OpenAPI。员工目录使用 OIDC 令牌，仅返回当前授权的已发布版本。

对支持 MCP 2026-07-28 Skills 扩展的客户端，可在企业专用 MCP 网关发布 `skills/list`、`skills/get`，并将每个文件映射为 `skill://<企业命名空间>/<skill-name>/<相对路径>` 的 `resources/read`。响应含完整 frontmatter、文件摘要和大小；不把所有 Skill 内容塞进工具描述。旧客户端先通过普通目录或显式 URI 使用，是否自动安装由 Host 决定，Admin 只提供资源与授权。

## 数据与安全要求

新表至少包含 Skill 资产、不可变版本、文件清单、发布指针、用户／部门授权以及审计记录。文件可放受控对象存储或数据库，数据库元数据与内容摘要必须同事务或可恢复地对应。迁移遵守项目的 `COMMENT ON TABLE/COLUMN` 简体中文注释要求。任何下载／读取都重新检查企业、发布状态、当前授权和内容摘要；路径绝不能直接拼接到本机文件系统。对导入包的扫描和读取不执行其脚本、模板或 Markdown 中的指令。

## 验收

1. 导入合法多文件 Skill，管理端可核对 frontmatter、清单、摘要与版本差异；非法路径、符号链接和超限包被拒绝。
2. 员工 A 有授权、员工 B 无授权；目录、`skills/get`、所有 `resources/read` 均一致执行限制，撤权后新的读取失败。
3. 更新发布产生新摘要，客户端能发现变化；旧版本不可被未授权 URI 绕过。
4. Skill 依赖的 MCP 工具在连接撤权后仍无法调用；Skill 文件内容不能提高调用权限。
5. Web 与桌面 Host 至少各完成一次真实读取和用户批准流程；不同客户端不支持扩展时呈现明确兼容提示。
