# AI 调用可靠性与排障

适用于 AI 小说、漫剧和试衣（换装），以及它们共用的模型网关和供应商适配器。修改报错、超时、输出校验、重试或后台任务恢复前，先用这份约定定位最早失败的阶段。各模块的细节以现行代码和专项文档为准。

## 先确认失败阶段

一次操作通常经过「接收请求或入队 → 路由与鉴权 → 上游调用 → 响应组装 → 结构解析 → 业务校验 → 保存或发布」。后台任务还要区分供应商的任务状态和本站的任务状态。界面的一条失败提示不能说明是哪一层出错。

1. 记下入口、发生时间、`request_id` 和已有的业务任务标识。有版本切换时先确认当前服务进程确实加载了新代码；浏览器刷新不会替换旧 Go 二进制。
2. 在[模型调用日志](model-call-logs.md)里先核对 `source`、`operation`、实际供应商和上游模型 ID、状态、耗时及错误。有阶段时间的文本调用再查看响应头、首次思考、首次正文与响应读完的时间。没有记录时先查请求是否到达、路由或鉴权是否拦截、调用记录是否保存失败。
3. 把调用记录和业务错误或任务事件对齐。同步请求的 HTTP ID 由[中间件](../internal/httpserver/server.go)传入网关，同一次请求的多次调用可按时间区分。后台任务不一定沿用创建请求的 ID，应使用业务任务或片段关联；缺少直接关联时在授权范围内按来源、操作、调用身份和时间核对。
4. 只在需要时读取受权限控制的请求和响应副本。检查日志是否截断或脱敏。用合成数据或授权的失败响应在本地重放解析和校验，避免先重新消耗模型额度。记录结论时只保留足以复现的最小片段和元数据。

| 阶段 | 常见表现 | 修复边界 |
| --- | --- | --- |
| 请求准备 | 模型未启用、无权限、额度用完、格式或参数不受支持 | 核对实际路由、权限或参数，向用户说明可采取的操作。相同请求不会自行消除这类问题。 |
| 上游调用 | 连接失败、无响应、上游返回错误、请求被取消 | 查实际超时归属、HTTP 状态和供应商错误码。HTTP 200 的 SSE 仍可能包含终止错误帧。只有明确可重试、仍有预算的暂时故障才补做。无上游响应时，日志中的网关状态可能是本地归类。 |
| 响应接收 | SSE 提前断开、没有完整结束标志、达到输出长度或读取上限 | 保留可用草稿或检查点，区分模型输出截断与日志副本截断；核对输出预算、上下文和实际代理行为。 |
| 结构解析 | 上游 200，但内层 JSON 损坏、字段缺失、类型不符 | 能确定且不改变原意的格式问题在本地修复，再走原校验。其他问题按当前步骤的预算定向重试。 |
| 业务校验 | 重名、章节或分镜范围越界、引文不符、框坐标或图片格式不合格 | 校验要能说明具体失败条件。只调整失败字段或片段，保留已通过的产物，禁止把缺失数据补成事实。 |
| 保存与恢复 | 版本冲突、任务租约过期、图片下载或写库失败 | 先核对是否已扣费、是否已有结果或上游任务 ID，再决定续查、重试保存或显式发起新尝试。不能把保存失败当成需要重新推理。 |

调用记录 `success` 表示该次适配器的调用阶段成功，不能替代应用层校验和保存。图片适配器可能在调用阶段就完成部分解码或下载，各入口的成功边界应以实现为准。新增真实推理、媒体生成、供应商任务状态查询必须复用 [`ExecuteRecordedCall`](../internal/modelgateway/recorded_call.go)，每次真实调用各记一次并保留稳定的来源和操作。业务校验结果用业务日志、阶段事件或任务状态记录，不能再造一份调用用量。

## 后台生成约定

- 面向用户的 AI 生成默认使用后台任务。提交接口负责鉴权、校验和登记任务，返回 `202` 与任务标识或状态。任务用独立且有期限的上下文执行。需要即时反馈的短推理可以在验证实际耗时后保留同步，并设置明确的请求预算。只读查询、短校验及纯保存可同步。
- 状态与成果由服务端保存。刷新、切页或暂时断网后按业务对象或任务标识接着查看原任务。页面展示运行阶段和可处理的失败，只限制会与任务冲突的操作。轮询只读取本站状态，供应商状态查询由后台执行，任务结束后停止轮询。页面进度流断开只影响进度展示。
- 同一目标和版本的重复提交应复用正在执行的任务或返回冲突。写回前校验任务归属、有效租约和业务版本，防止过期任务覆盖用户的新内容。阶段性成果通过校验后及时保存，后续摘要、审稿或发布失败时仍可从已有成果继续。调用记录和任务状态尽量使用同一业务标识关联。
- 页面离开可继续与服务重启可恢复是两项能力。对已有检查点或供应商任务 ID 的任务，恢复时优先复用成果或查询原任务。只有进程内执行的任务需要说明中断后如何收敛，租约过期后按业务规则结束或重新领取。

## 超时和重试怎么改

- **先列截止时间。** 按实际链路区分浏览器取消、部署代理、服务端请求上下文、供应商的连接或响应头、任务总时限、租约和保存状态的短时限。Go 服务的 30 秒 `ReadTimeout` 是读入站请求用的，当前 `WriteTimeout` 为 0。演示 Nginx 的 `proxy_read_timeout` 是 31 分钟，生产部署需核对实际配置。上游 SSE 和本站向页面发送进度的 SSE 是两条链路。模型流式返回也不代表业务接口会边生成边响应页面。[Go 服务配置](../internal/app/app.go) · [演示代理配置](../deploy/demo/nginx.conf) · [供应商客户端](../internal/modelprovider/gateway.go)
- **改最早触发的那一层。** 父上下文更早到期时，调大子调用时限不会延长任务。响应头很慢、首段正文很慢、传输中断、应用解析慢、保存慢要分别验证。遗留同步生成链路频繁触及页面或代理预算时，按后台生成约定迁移。后台结束后的日志与状态保存使用独立、有限的上下文。统一调用记录在原上下文取消后最多另用 15 秒。
- **算一次操作的完整重试预算。** 前端重新请求、后端校验重试、工作流续跑、供应商查询各是不同层级。修改任一层时写清触发条件、最大次数、总时限和耗尽后的提示。网络或 429／5xx 是否可重试按具体入口确认。对明确失败的输出优先局部修复，对暂时无法确认是否已提交的生成请求不能盲目重发。
- **恢复已有工作。** 有检查点的流程按实际输入、模型与版本核对后复用。已获得供应商任务 ID 时，优先查原任务状态。用户再次提交、服务重启、租约失效和迟到结果都不能静默覆盖定稿或上一次成功媒体。修改预算时一并核对队列租约、迟到写回保护和轮询停止条件。
- **模型参数按实际能力选。** 按真实供应商、接口、上游模型 ID 和任务限定参数。改采样、思考或结构化输出时用固定输入对照，检查业务验收结果和耗时，避免把单一场景的设置扩散到其他功能。

## 已验证案例

### 从旧定稿找回未进入摘要抽样的地点

故事档案按定稿保存人物、名字和别名、地点、伏笔以及原文证据。写正文、审稿和按意见复核会按本章目标、作者要求、草稿中的名称和关联对象查找有用的历史证据，最多带 12 条匹配事实和 3 组相关待确认冲突。最近正文与摘要仍提供章节衔接。档案查询失败会记诊断日志，本章可用原来的资料继续生成。候选只取当前章以前仍有效的定稿，未确认的冲突只作为待核对资料。位置移动和伏笔推进保留章序，程序只就别名归属、本名、出生地等固定资料的不同记录请求取舍。

已用模拟模型验证第 12 章的账册藏址虽然不在第 50 章的摘要抽样里，写作和审稿仍能从档案拿到原文。关系图展示档案中有出处的关联，和写审使用同一份事实；抽取遗漏和名称无法匹配时仍可能查不到旧线索。[旧章召回回归](../internal/novel/story_memory_test.go) · [档案召回规则](../internal/novel/story_memory_context.go)

### 刷新取消了正在生成的小说正文

2026-11-07，第 1 章正文生成收到百炼 HTTP 200 并开始读取思考。约 14 秒后请求以 `context canceled` 结束，紧接着页面重新读取作品。调用记录无正文增量，作品仍为已确认大纲的版本。原生成接口把上游流绑定在页面请求上，断开后没有可续查的任务。

工作台现在先登记章节任务，刷新后查询同一任务。已通过校验的正文在补摘要或审稿前单独保存。用模拟模型验证页面请求取消后后台继续、重复提交复用任务、审稿失败时草稿仍在，以及迟到结果不会覆盖作者修改。用本地 Redis 验证了进度更新、租约过期和旧任务写回保护。用模拟接口在浏览器里验证了提交后立即刷新、重新看到生成进度和草稿，并确认只有一次提交。[章节任务回归](../internal/novel/draft_job_test.go)

### 小说灵感的内层 JSON 含未转义换行

2026-11-07，百炼 `deepseek-v4-flash-0731` 的灵感优化调用返回 HTTP 200，网关记为 `success`。应用随后报 `invalid character '\n' in string literal`。外层流式包可以正常读取，拼出的内层 JSON 字符串包含未转义的换行，预览解析失败。提高超时或更换模型链接不能修复这类错误。

当时在灵感预览解析处修复，只给 JSON 字符串内的字面换行、回车和制表符补转义，重新按原规则解析并校验。仍有格式错误时使用现有一次重试预算，耗尽后给出格式错误提示。本地用原响应重放，得到完整 2150 字并保留 10 处换行，未再次调用模型。该修复后来并入共用小说解码器。[预览实现](../internal/novel/idea_refinement.go) · [回归用例](../internal/novel/refinement_test.go)

### 按审稿意见改稿收到正常结束的流，但内层 JSON 不完整

2026-11-09，按审稿意见修改第 2 章时，百炼约 28 秒后返回 HTTP 200，流以 `stop` 和 `[DONE]` 正常结束。模型调用记录为 `success`，响应副本未截断。同一请求的应用日志显示 `invalid character '\n' in string literal`，工作台收到 502。重放发现正文字符串没有闭合引号，摘要字段也没有出现。补转义仍无法解析。此次操作停在生成改稿之后、复核和保存之前，旧稿保留。

### 改稿已保存，但正文和审稿意见看起来没变

2026-11-09，同一章按意见改稿的首次输出不完整，补做后的结果通过了格式检查并保存。逐字比对发现正文与原稿完全相同，只有连续性摘要更新。复核将两条旧意见均判为未解决。应用 HTTP 200 和作品版本递增表示请求完成并保存，不能用于判断正文发生了修改。

按意见改稿保存时单独记录正文和摘要是否改变，工作台重新加载后展示比较结果。当前审稿状态单独显示，仍未解决的意见继续列出。用模拟改稿验证仅摘要变化、重新读取及手动改稿后旧结果不再显示。[改稿结果回归](../internal/novel/review_revision_test.go)

此前的模型合约要求整章正文，服务端只校验正文是否存在且符合长度，复制原稿也能进入复核和保存。按意见改稿现在要求模型为局部改动给出意见编号、原句和替换文本。原句必须在原稿中唯一定位，替换不能重叠或只有空白差异。先校验所有改动，再按位置应用，其他文字逐字保留。正文不变时先复核，只有意见确属摘要问题且摘要已修好，或意见确实不适用，才接受结果。首次有效改稿部分通过且没有新问题时，可用同一份单次补做预算，结合复核指出的具体缺口修剩余意见，再按原意见全集复核。补改必须减少待办并保住已经解决的意见，否则保留首稿。复核确认所有原意见仍未解决时保留原稿。格式错误、无效候选或部分通过合计最多补做一次，改稿和复核总预算 30 分钟。[改稿实现](../internal/novel/review_revision.go) · [改稿回归](../internal/novel/review_revision_test.go)

对同一份草稿的真实百炼预演中，首稿实质修正了第一条，第二条仅换了官职仍未通过。重放这份首稿并使用复核反馈补改后，第二条在原有对话中补出了指向调查对象的口供，两条原意见均经模型复核通过。预演没有写回作品。

### 改稿引文抄错，模型返回成功但后端找不到原句

2026-11-09，第 2 章按意见改稿的两次模型调用均为 HTTP 200，首轮把原文双引号抄成单引号，补做时又把另一处引文换成了不同文字。旧实现要求每条引文逐字且唯一命中，任意一条定位失败都会拒绝候选，最终响应 502，未写回原稿。

服务端按当前正文切分并编号，模型只返回选中的编号和该段的完整替换文本。长行按句末优先切块，单块最多 800 字。应用时使用生成编号时的原始字节范围，重复文本也能区分位置，未选中的内容和分隔符不改动。无效或重复编号走原有补做预算，旧引文格式仍只接受精确且唯一的匹配。[改稿定位](../internal/novel/review_revision.go) · [回归用例](../internal/novel/review_revision_test.go)

真实编号改稿预演已成功定位两处改动，但复核误把旧稿中已删除的句子当成新稿证据。复核输入现在只带当前章新稿和改动后的片段，程序用旧稿校验是否属于新增问题。重放同一份真实编号改稿并调用百炼复核时，两条意见均通过，预演未写回作品。仍有补做预算且全部旧意见未解决时，从原稿按反馈重试一次；已解决一部分时继续从首稿修剩余意见。两种情况都重新编号，二次结果不改善时保留可用首稿，全部意见仍未解决时保留原稿。

## 后续怎么把结论留住

每次修复发现可复用的新情况时，在本页或对应模块文档记下「用户看到的现象、最早失败阶段、用什么证据确认、实际修在哪里、如何复现与验证」。若改了模型参数、超时、重试次数或恢复行为，同时更新上方实现索引或专项文档。只验证到模拟上游就写模拟上游，真实模型结果单独注明样本和条件；还未确认的原因标为待查。

常规先跑受影响模块和接口的回归。以下命令覆盖当前入口，按改动范围选用：

```sh
go test ./internal/novel ./internal/drama ./internal/tryon ./internal/app ./internal/modelgateway ./internal/modelprovider
go test ./internal/httpserver -run 'Test(Novel|Drama|TryOn|GatewayE2E)' -count=1
```

涉及队列租约、过期和迟到写回时，按[开发指南](development.md)使用专用 PostgreSQL 测试库跑迁移集成用例。涉及新供应商参数或实际模型输出时，再用授权的合成样本对照，经过现有调用记录链路。禁止把密钥、用户正文、原图或完整失败日志作为仓库测试样例。

验证后台迁移时，用可控的慢响应确认提交能尽快返回、刷新能找回同一任务、重复提交不会另起一次生成，以及后续处理失败仍可读取已保存的成果。涉及写回时，覆盖任务运行期间用户修改目标后出现的版本冲突。
