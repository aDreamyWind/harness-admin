# 漫剧批次解析工作流

新建解析和“重新解析”使用第二版流程：美术提取与剧情整理 → 整批分集规划 → 按规划逐集写作 → 逐集审校 → 正式保存。阅读片段只用于模型输入，不直接当作集界。规划按连续原文单元完整覆盖整批，检查遗漏、重叠和越界；每集最多分配 16000 字符原文。

“重新解析”清除本次阶段检查点和创作事件，从头执行，正式资产和剧集在新结果全部通过后才整体替换。“从此处继续解析”只用于失败且范围未变化的任务，沿用保存的模型和概览快照，跳过所有已完成检查点。独立任务并行时，续跑会恢复全部失败和未执行步骤，保留后来独立完成的步骤。旧版任务沿用原有流程继续；点击重新解析后进入第二版。

剧情整理记录每个原文单元的事件摘要，导演据整批摘要和原文长度规划分集；逐集写作时读取对应的完整原文。输出必须引用已提取的角色、场景和道具。审校依据原文检查事件、因果、状态和可拍摄性，未通过时只修正对应集并再审一次，再失败则保留成果等待续跑。每个模型或格式失败最多自动重试一次，不无限循环。

独立的美术和剧情任务初始串行；完成请求耗时超过 45 秒后，后续任务并行上限升至 2；发生自动重试后降回 1。逐集写作与审校顺序执行，保留上一集梗概用于衔接。每次模型调用最多等待 10 分钟，整批最多 8 小时，继续使用用户配置的文本模型。

模型使用流式输出；不展示模型推理字段。已生成的剧本正文以待校验预览展示，完成 JSON 和业务校验后写入步骤表。原始请求、完整原始 SSE 响应、耗时、用量和失败详情仍保存在模型调用日志。真实的开始、接收、完成、重试、修正和调度事件保存到事件表，经 SSE 推送；刷新后读取检查点，断线后按递增事件序号续传。

正式业务数据继续使用角色、场景、道具、剧集和关联表的明确字段。步骤结果和运行上下文是解析检查点，以文本保存结构化输出，不作为业务查询的唯一来源。

新增迁移 44。可通过 `DATABASE_URL=... go run ./cmd/migrate` 单独执行迁移；启动服务也会自动迁移。新增 `/resume`、`/events` 接口及扩展的 `/progress` 结构见 OpenAPI。

第 45 号迁移将每集资产关联的唯一键调整为“剧集＋项目资产”。状态说明不参与资产身份判定，已有重复关联合并时完整保留非空说明。同一资产在本集的多个状态按换行存放；目录描述始终通过真实资产主键读取。重复添加返回原关联，移除关联不删除资产目录数据。页面添加窗口将已有关联勾选并禁用；资产标签悬浮展示目录描述及本集状态。批次资产总分组和三类列表都可独立折叠，桌面侧栏随正文滚动保持固定。
