# 漫剧批次解析工作流

新建解析和“重新解析”使用第二版流程：美术提取与剧情整理 → 整批分集规划 → 按规划逐集写作 → 逐集审校 → 正式保存。阅读片段只用于模型输入，不直接当作集界。规划按连续原文单元完整覆盖整批，检查遗漏、重叠和越界；每集最多分配 16000 字符原文。

“重新解析”清除本次阶段检查点和创作事件，从头执行，正式资产和剧集在新结果全部通过后才整体替换。“从此处继续解析”只用于失败且范围未变化的任务，沿用保存的模型和概览快照，跳过所有已完成检查点。独立任务并行时，续跑会恢复全部失败和未执行步骤，保留后来独立完成的步骤。旧版任务沿用原有流程继续；点击重新解析后进入第二版。

剧情整理记录每个原文单元的事件摘要，导演据整批摘要和原文长度规划分集；逐集写作时读取对应的完整原文。输出必须引用已提取的角色、场景和道具。审校依据原文检查事件、因果、状态和可拍摄性，未通过时只修正对应集并再审一次，再失败则保留成果等待续跑。每个模型或格式失败最多自动重试一次，不无限循环。

独立的美术和剧情任务初始串行；完成请求耗时超过 45 秒后，后续任务并行上限升至 2；发生自动重试后降回 1。逐集写作与审校顺序执行，保留上一集梗概用于衔接。每次模型调用最多等待 10 分钟，整批最多 8 小时，继续使用用户配置的文本模型。

模型使用流式输出；不展示模型推理字段。已生成的剧本正文以待校验预览展示，完成 JSON 和业务校验后写入步骤表。原始请求、完整原始 SSE 响应、耗时、用量和失败详情仍保存在模型调用日志。真实的开始、接收、完成、重试、修正和调度事件保存到事件表，经 SSE 推送；刷新后读取检查点，断线后按递增事件序号续传。

正式业务数据继续使用角色、场景、道具、剧集和关联表的明确字段。步骤结果和运行上下文是解析检查点，以文本保存结构化输出，不作为业务查询的唯一来源。

新增迁移 44。可通过 `DATABASE_URL=... go run ./cmd/migrate` 单独执行迁移；启动服务也会自动迁移。新增 `/resume`、`/events` 接口及扩展的 `/progress` 结构见 OpenAPI。

第 45 号迁移将每集资产关联的唯一键调整为“剧集＋项目资产”。状态说明不参与资产身份判定，已有重复关联合并时完整保留非空说明。同一资产在本集的多个状态按换行存放；目录描述始终通过真实资产主键读取。重复添加返回原关联，移除关联不删除资产目录数据。页面添加窗口将已有关联勾选并禁用；资产标签悬浮展示目录描述及本集状态。批次资产总分组和三类列表都可独立折叠，桌面侧栏随正文滚动保持固定。

第 46 号迁移新增批次名称及手动命名标记。第二版解析在整批分集规划完成后，通过独立模型调用生成简短批次名，作为可恢复的“批次命名”步骤记录；手动命名后跳过自动起名，运行中修改的名字也不会被 AI 覆盖。编号继续单独递增，双击批次详情名称可编辑，Enter 或失焦保存，Escape 取消。旧批次初始显示“未命名批次”，可直接手动改名；重新解析会进入自动命名流程。

资产的 `origin_batch_id` 保存首次提取的批次，历史数据依据现存最早批次记录回填；后续批次使用同一资产时保留来源。应用批次从实际剧集资产关联表推导并按批次ID去重，不把“提取到”混作“应用了”。来源和应用名称均联表实时读取，改名后不需要复制或改写资产标签。资产卡片上的标签可跳转到对应批次。

批次详情的资产总分组和当前角色／场景／道具列表标题采用两层吸顶，滚动时可直接点击折叠。项目资产页改为封面画廊：角色竖版、场景横版、道具方形，悬浮或键盘聚焦显示简介和预览，预览中展示完整描述、外貌、音色和来源／应用批次。窄屏保留双列角色／道具和单列场景；触屏常驻预览入口。当前图片生成和自由画布尚未接入，使用“暂无图片”封面并明确禁用画布按钮，不虚构形象数量。

视频分集首版以正式分集剧本为制作入口，使用 `drama_script_episodes.id` 关联，不复制标题、正文或资产。新增只读接口 `/projects/{id}/video-episodes` 和 `/projects/{id}/video-episodes/{episodeId}`，均按当前企业与用户隔离。已有解析完成的剧本立即出现在视频列表；旧概览中没有批次或正文的分集规划不进入制作列表。按批次编号及批内集号生成项目内展示序号，原批内集号独立保留，身份始终使用主键。解析进行中列表每五秒刷新，完成后停止轮询；可按来源批次筛选。

单集制作页通过 URL 的 `section=videoEpisodes&episode=分集剧本ID` 保持刷新位置。左侧仅展示真实剧集资产关联，状态说明单独展示，可预览和折叠；右侧为待拆分状态，支持查看本集正文、定位并展开来源批次的准确剧集。来源批次范围改变、重解析或解析异常时提示核对，保留现存剧本入口。此阶段不调用模型、不写入分镜或视频记录，不显示虚构的片段和进度；AI 分镜拆分与合成按钮明确禁用，等待后续实现。后续接入实际分镜及视频成果前，需实现剧本修订、制作版本及重解析保护，避免现有批次重解析替换剧集时删除制作成果。

第三版解析（迁移47）把初始项目概览与批次事实分离。运行快照只带画风、画面比例和模型；不把最初十万字的故事梗概、背景、设定作为后续批次事实。本批按原文单元提取事实及逐字引文，程序校验引文属于该单元，并生成完整原文中的字符位置与稳定事实ID。全批规划只选择连续单元和范围内的事实ID；梗概与结尾依据由实际引用事实组成，不沿用自由编写的跨集梗概，遗漏范围内证据或引用后集证据都会触发校验。

每批另存“本批上下文”检查点，范围是当前批次，起点前最多补读6000字符用于承接，未读的更早剧情不作推断。上下文结构化文本属于可恢复的解析检查点，不代替正式业务表字段；现有项目概览和用户手动内容不会被改写，累计更新项目概览留到下一阶段。单集导演只接收本集原文、范围内证据、此前承接及统一资产名称，不接收全批资产描述或整批上下文摘要，避免后文信息倒灌。每项资产引用还须附带可在本集原文找到的sourceQuote。

审校问题使用明确字段表drama_review_issues，记录事实/衔接/关键因果/表达四类问题、阻断或建议级别、原文与剧本引文、字符位置及open/resolved状态。表达建议不阻断。修正输出唯一匹配的局部替换，不重写整集；已修正问题继续作为回归约束。每次执行最多两次局部修正，仍有事实问题时保留检查点并停止；继续解析先修正当前未完成问题，已通过剧集复用同输入的审校结果。原始模型请求与响应继续由模型调用日志保存。

每次重新解析生成新的analysis_run_id，继续解析保留同一标识。历史审校记录保留但不混入新运行。步骤的input_hash包含工作流版本、运行标识、模型及完整输入；输入变化或从第二版升级时，不能复用旧协议的步骤结果。第二版失败任务首次继续将升级为第三版并重建证据及规划；第一版旧流程仍保留兼容路径。重试开始时保留上次成功的正文，修正模型失败不会先清空成果。GET进度接口扩展context、reviewIssues及规划sources供界面查看。

这些校验能确认引文与位置、阻止跨范围引用，但语义是否忠于原文仍需要模型审校，不能视为数学意义上的事实证明。模型超时、JSON格式或内容错误仍会明确记录并可继续处理。
