# AI 试衣设计草案

首版入口在「AI 应用管理 / AI 试衣」，位于「AI 小说」下方。上传参考图后，衣物可识别或框选目标并生成完整单品图，姿态提取动作和视角并生成人台图，人物生成保留身份特征的 2D 插画或写实全身底图。确认生成图后存入当前用户的素材库。试衣台一次可选择一至四件衣物，可将两至四件已有单品保存为套装。试穿提交后在试衣台下方查看进度，排队或生成时仍可继续提交新搭配，历史结果可在「试穿记录」查看。

人物库、衣物库和姿态库支持删除自建素材。未用于试穿的素材直接删除，已有试穿记录的素材从素材库和新试穿的选项移除，历史记录仍可打开当时的参考图和试穿结果。

打开或刷新试衣台时，从空白搭配开始。写实男女模特和动漫男女角色在人物库中供手动选用，卡片封面突出面部，试穿使用全身参考图。试衣台下方以图片卡展示正在处理的任务和最近结果，完整历史可在「试穿记录」查看。

启用首版需要运行迁移 65，并在模型目录为使用者启用可用模型。百炼 Qwen3-VL 可以用于衣物识别，Qwen-Image 2.1 或 3.0 可以生成人物和试穿图。使用 OpenAI 兼容供应商试穿时，图片模型需标记「视觉」，供应商的图片生成接口须支持 `image` 数组。模型调用沿用企业模型策略，排查日志来源为 `ai_tryon`。

建议在 Harness Admin 增加「AI 试衣」模块，包含人物库、衣物库和试衣台。人物库保留「2D 插画」「3D 角色」「真人」三个入口。衣物和人物可以反复组合，每次试穿保存独立结果。首版目标是让设计师快速看衣服穿在不同人物身上的视觉效果。真实尺码、生产打版、布料物理仿真分别需要额外输入和独立验证。

## 三类人物怎样创建

| 入口 | 怎么建人 | 试穿怎么做 | 首版范围 |
| --- | --- | --- | --- |
| 2D 插画 | 选动漫、线稿、半写实等画风，输入人物特征，或上传角色设定图；选定一张正面全身主图 | 把主图和衣物图一起交给参考图编辑模型，要求保持人物身份、画风、姿态和比例 | 支持建人物；试穿质量达标的画风可以开放，其他保留试验入口 |
| 真人 | 上传单人全身照，或用文字生成写实模特；两种来源明确标记「真实照片」「AI 生成」 | 专用试穿模型读取人物图、单品图及衣物类别，生成同一姿势的试穿图 | 首版优先做上衣、下装；连衣裙按模型和样本验证后开放 |
| 3D 角色 | 选择可调体型的模板，或导入已绑骨骼的 GLB / VRM；通过旋转、缩放和姿势预设检查 | 可把 3D 角色固定姿势渲染成图后做 2D 试穿；要让衣服随模型旋转，衣物必须有适配该角色的 3D 网格 | 首版可先用预置角色验证旋转和导出试穿底图；真实 3D 换衣单独验证 |

**人物要先定稿，再换衣。** 上传人物参考图时优先选择单人、脸部清晰、遮挡少的照片或插画。生成正面全身底图后，核对脸型、发型、体型和画风，再保存生成图。后续换姿势或增加侧面图时，以选定的主图作为身份参考，每张图单独确认，减少从上一张试穿图反复派生造成的身份漂移。3D 渲染图可同时记录角色版本、相机和姿势，方便复现。

2D 和真人在技术上都可以是图片。「真人」是产品入口，其中可包含 AI 写实模特；「2D 插画」指插画风格；「3D 角色」指可旋转的真实模型。系统分别记录表现形式、风格、素材来源。渲染得像 3D 的图片仍按图片处理。

## 衣物怎样入库

现有「服装设计」工作台已经有「上传或粘贴 → 百炼视觉模型给出可见单品和矩形框 → 用户点选或重框 → SAM 2 用框和点细化轮廓 → 人工确认」的闭环。复用这个交互以及坐标归一化、过滤重叠框、遮罩编辑和错误回退。把识别类别从当前的「服装」细化为「上衣、外套、下装、连衣裙」，下装可再细分裤子和半裙；鞋履、包袋、首饰、其他配饰继续保留。业务分类与模型支持的类别分别维护，例如「外套」可按已验证模型映射为上衣，也可在某个模型上显示暂不支持。

用户可以上传商品平铺图，也可以从一张穿搭照中识别多件衣物。勾选候选或手动框出目标后，可分批提交后台生成，每批最多八件。提交后可继续选择同一张图里的其他单品，也可关闭添加窗口。衣物库显示每件的排队、生成、失败和待确认状态。生成模型使用原图和定位特写生成独立单品图，用户检查款式、颜色、纹理及遮挡补全部分，再确认入库。失败可单独重试，待确认和失败任务在近期保留。

衣物库保存确认采用的生成图。输入图和定位框用于当前编辑会话，遮挡或未入镜的部分由模型推测，预览时由用户判断能否采用。后续若支持追溯参考来源和多视角，可进一步区分原图可见、用户补图与 AI 补全。已有款式图或 SVG 可以作为设计参考附件，3D 另附适配网格。

## 试衣台交互

试衣台采用三栏。左侧选人物和底图，中间看原图／结果，右侧选衣物、可选姿势和生成方式。人物卡和衣物卡都有「去试穿」，点击后预填其中一侧。可以在同一页补上传，完成后回到当前组合。点击生成前展示本次采用的人物底图、衣物图和姿势图，并标明各自用途。

1. **选人物。** 默认使用已采用的正面主图，并保留人物当前姿势。希望换姿势时，可选带视角的姿势卡或上传参考图。专用试穿引擎只支持保留姿势时，先生成并确认新底图，再试穿。人物缺少合适的视角时，说明缺少哪部分并提供「换底图」。3D 角色可选择「生成试穿图」，有兼容资产时也可以选择「3D 换衣」。
2. **选衣物。** 一次可试一至四件。多件衣物组成一张分格参考板，提示词按格对应每个单品，并区分外套、内搭和配饰。套装保存衣物组合，选中后可一次加入试衣台。
3. **生成。** 显示「排队中／生成中／已完成／失败」。用户离开页面后可从试穿记录回来。默认每次生成一张；重试显式发起，重试不会覆盖以前成功的图。后续如支持叠穿，先限制清晰的上衣、下装、外套槽位，分别验证遮挡顺序和多次生成造成的细节变化。
4. **对比与采用。** 并排查看人物原图、衣物参考和试穿效果；标记「脸变了」「款式变了」「纹理丢了」「姿态变了」等问题。可保存为一套搭配、下载或保留历史。重新生成从冻结的原始组合出发；选用新的底图或衣物版本时建立新组合。

「衣物抠图遮罩」描述源照片上要提取的那件衣物；「人物换装遮罩」描述目标人物上允许改动的区域。两个遮罩的位置和用途不同，分别保存和编辑。首版可以只提供衣物遮罩编辑，遇到人物换装失败先提示换图。

## 在 Harness Admin 的实现边界

- 使用独立业务模块管理人物、衣物和试穿记录。参考现有[漫剧资产形象](ai-drama-workflow.md)的父图派生、版本引用、权限和任务状态设计，优先复用生成适配器及预览交互；试衣人物不挂到某部漫剧的项目下。
- 最少持久化四类信息：人物及其参考图版本、衣物及其素材版本、试穿任务、试穿结果。试穿任务冻结具体的人物图、衣物图、模型版本和参数；重复点击使用同一任务，明确重试创建新尝试。媒体走有权限检查的存储与下载接口，真人照片按归属限制访问，调用日志保留脱敏的请求和响应。
- 素材识别和生图使用 `modelgateway.ExecuteRecordedCall`，业务来源为 `ai_tryon`。操作分别为衣物识别 `garment_detect`、衣物重建 `garment_reconstruct`、姿态标准化 `pose_standardize`、参考图重建人物 `person_reconstruct`、文字生成人物 `person_generate` 和试穿生成 `tryon_generate`。轮询本站任务记录不触发上游推理。
- Go 业务层只依赖识别、分割、生成和存储的小接口。人物生成和衣物识别优先沿用现有百炼供应商；真人试穿可以对照有账号权限的托管接口，例如[阿里云电商经营助手 AiTryOn](https://help.aliyun.com/zh/aidge/api-aidge-2026-04-28-aitryon)，它有独立的签名接口，不能按当前百炼通用图片端点直接复用。自部署推理可接独立运行的进程，业务仍留在模块化单体内。首版依模型能力配置决定可选品类；稳定后再决定默认引擎。接口、权限和迁移随实现同步补测试、OpenAPI 和中文数据库注释。

## 推荐验证顺序

1. **先做同图对照。** 准备可用于测试的 24 组真人组合（上衣、下装、连衣裙各 8 组，覆盖平铺和穿搭参考、印花和遮挡），12 组 2D 组合（不同画风和体型），再加多人、局部、严重遮挡等失败样例。真人对照 FASHN 研究版与有权限的托管接口；2D 用参考图编辑验证。记录脸和发型是否保留、姿势与体型是否变化、颜色／纹理／领口／下摆是否正确、失败率、端到端耗时。把同一件衣服的原始穿搭照、裁剪图和人工确认的抠图分开试，决定不同模型默认吃哪种输入。
2. **交付最短闭环。** 先上线人物建档、衣物识别入库和真人单件试穿。人物可用预置样例、上传真人图或生成写实模特。2D 可以先建档，按试穿结果开放通过验收的画风。衣物库可以保存配饰，试衣台只开放已验证品类。样本验收要能清楚区分人物保真、衣物保真和阻断错误；不能只用「好看」作判断。
3. **单独验证可旋转的 3D 换衣。** 做一个骨骼／人体模板、一件上衣和一件下装，验证旋转、基本姿势、穿模、遮挡和导出。用这一套样板估算每件 3D 衣服的制作与质检成本，再扩体型、品类和布料模拟。如果用户只需要出图，可直接使用 3D 底图进入 2D 流程。

当前结论来自本地代码、官方仓库、模型卡、论文，以及澜姿和 Open Pose & Costume 的在线交互核对。尚未用业务样本运行模型。默认模型、支持的画风和品类，以对照结果为准。
